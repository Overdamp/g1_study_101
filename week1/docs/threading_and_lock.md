# Thread และ Lock (จากงาน 1.3 นับ Hz)

## 1. thread คืออะไร
ปกติโปรแกรมทำงานทีละบรรทัด เหมือนมี**คนทำงานคนเดียว**
พอใช้ callback ของ SDK โปรแกรมจะมี**คนทำงาน 2 คน**ทำพร้อมกัน

| คน | ทำอะไร |
|---|---|
| **main thread** | `sleep(1)` → ตื่นมาอ่านตัวนับ → print → นอนต่อ |
| **thread ของ SDK** | รอข้อความ → มีข้อความเข้ามา → เรียก `handler` → `count += 1` |

ทั้งสองคนใช้ตัวแปรเดียวกัน คือ `counter.count`

> callback **ไม่ได้**อยู่ thread เดียวกับ `main` (คำถามทวนข้อ 3)
> `sub.Init(handler, 10)`: ถ้าคิวมากกว่า 0 SDK จะสร้าง thread แยกขึ้นมาเรียก handler

## 2. ปัญหา: race condition
`count += 1` ดูเหมือนคำสั่งเดียว แต่จริงๆ มี 3 ขั้น: **อ่าน → บวก → เขียนกลับ**
ถ้าสอง thread ทำงานสลับกันพอดี:

```
count = 500
SDK  : อ่าน count ได้ 500
main : อ่าน count ได้ 500  → เอาไป print
main : เขียน count = 0      (รีเซ็ต)
SDK  : 500 + 1 → เขียน count = 501   ← เขียนทับค่าที่ main เพิ่งรีเซ็ต
```

ผล: วินาทีถัดไปนับได้ประมาณ 1000 แทน 500 **ตัวเลขเพี้ยนโดยไม่มี error ใดๆ**

## 3. Lock = กุญแจห้องน้ำที่มีดอกเดียว
```python
self.lock = threading.Lock()   # สร้างกุญแจ 1 ดอก

with self.lock:                # หยิบกุญแจ (ถ้าคนอื่นถืออยู่ ต้องรอ)
    ...                        # ข้างในนี้ทำได้ทีละ thread เท่านั้น
                               # ออกจาก with = คืนกุญแจอัตโนมัติ (แม้จะเกิด error ข้างใน)
```

กฎที่ต้องจำ
1. **ทุก thread** ที่แตะตัวแปรเดียวกันต้องใช้ lock **ตัวเดียวกัน** ถ้ามีคนหนึ่งไม่ใช้ ก็ไม่ได้ป้องกันอะไรเลย
2. ข้างใน `with` ให้**สั้นที่สุด** แค่อ่าน/เขียนตัวแปรที่ใช้ร่วมกัน ส่วนงานช้าๆ (คำนวณ, `print`) ทำข้างนอก
3. ถ้าข้างใน `with` เขียนไว้นาน อีกฝั่งต้องรอนาน callback อาจช้าจนข้อความค้างคิว

## 4. ใช้ใน `read_lowstate.py` อย่างไร
```python
# ฝั่ง SDK thread
def handler(self, msg):
    with self.lock:
        self.count += 1          # self.count ไม่ใช่ count ลอยๆ

# ฝั่ง main thread
with counter.lock:
    n = counter.count            # อ่าน
    counter.count = 0            # รีเซ็ต  ← อ่าน+รีเซ็ตเป็นขั้นตอนเดียว ไม่มีใครแทรกได้
print(n / dt)                    # print นอก lock
```

## 5. ทำไมสำคัญกับหุ่นจริง (สัปดาห์ 2)
- thread หนึ่งกำลังเขียนมุมเป้าหมายของ 23 ข้อต่อลงใน LowCmd
- อีก thread หยิบ LowCmd ไปส่ง**ตอนที่เขียนไปได้แค่ครึ่งเดียว**
- หุ่นได้คำสั่งที่ขาซ้ายเป็นท่าใหม่ แต่ขาขวายังเป็นท่าเก่า ⚠️

การนับ Hz ถ้าเพี้ยนบ้างก็ไม่เสียหายอะไร แต่**คำสั่งมอเตอร์ห้ามเพี้ยนเลย**

## คำถามทดสอบตัวเอง
1. ถ้าลบ `with self.lock:` ออกจาก `handler` แต่ยังเหลือ lock ใน `main` อยู่ จะยังป้องกันได้ไหม เพราะอะไร
2. ทำไมใน `handler` ต้องเขียน `self.count += 1` แล้วถ้าเขียน `count += 1` จะเกิด error อะไร
3. ถ้าย้าย `print` เข้าไปไว้ใน `with counter.lock:` ผลจะเป็นอย่างไร
