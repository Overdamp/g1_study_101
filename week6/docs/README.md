# สัปดาห์ 6: วิเคราะห์ข้อมูลหุ่นจริง: มอเตอร์ใช้ kp/kd ตามที่สั่งไหม

> สถานะ: **ร่าง** (เขียน 10/11/2026) ปรับได้เมื่อเริ่มจริง
> แผนตัวจริง: vault `05 Study/Study Plan.md` · ภาพรวม: `~/g1_study/STUDY_PLAN.md`

## เป้าหมาย
1. อ่าน log หุ่นจริง 3/11 (lowstate + lowcmd ที่อัด**พร้อมกัน**) แล้วจับคู่เวลาของสองไฟล์ได้เอง
2. เขียน **`pd_check` แบบง่าย** เอง: คำนวณแรงบิดที่ควรเป็น → fit ด้วย least squares → ได้ `kp x`, `kd x`, offset
3. อธิบายได้ว่าทำไม fit ทั้งไฟล์ได้ค่าต่ำ (ศอกขวา 0.61) แต่ fit เฉพาะช่วง step + offset ได้ ~0.96 และตัวเลขแต่ละตัวบอกอะไรเกี่ยวกับหุ่นจริง

## ทำไมงานนี้สำคัญ (เชื่อมทั้งคอร์ส)
```
สัปดาห์ 1  อ่าน LowState            → ที่มาของคอลัมน์ q, dq, tau (tau_est) ใน log
สัปดาห์ 2  PD: tau = kp·e + kd·ė     → สูตรที่จะ fit
สัปดาห์ 3  FSM                       → log นี้มาจาก sysid_motion.py ซึ่งส่ง lowcmd แทน g1_ctrl
สัปดาห์ 4  policy เทรนด้วย kp/kd ชุดหนึ่ง → ถ้ามอเตอร์จริงใช้ gain ไม่ตรง policy ก็เจอหุ่นที่ไม่เคยเห็น
สัปดาห์ 5  DR สุ่ม kp ×0.85–1.15       → ผลวัด kp x ของจริงต้องอยู่ในช่วงนี้ ถึงจะบอกได้ว่า "policy ทนได้"
สัปดาห์ 6  วัดจริง                     → ปิดวงจร sim ↔ real
```

## คำถามทวน (ตอบโดยไม่เปิดโน้ต)
1. `kp x` = 1 แปลว่าอะไร แล้ว 0.93 แปลว่าอะไรทางกายภาพ
2. ทำไมต้องหา delay ก่อน fit gain
3. offset ของ `tau_est` คืออะไร ทำไมกระทบ fit มากตอน gain ต่ำ (แขน kp 14.3)
4. omitted variable bias คืออะไร เกิดใน pd_check ได้ยังไง
5. ทำไม step ให้ `kp x` ที่เชื่อได้ แต่ `kd x` เชื่อได้น้อยกว่า chirp
6. ถ้า `kp x` และ `kd x` เพี้ยนไปเท่ากันทุกข้อต่อ น่าจะเป็นเพราะอะไร
