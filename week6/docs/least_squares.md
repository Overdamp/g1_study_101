# Least squares สำหรับ pd_check

## โจทย์
เรามีข้อมูล N แถว (lowstate ในช่วงที่สนใจ) แต่ละแถวมี P, D (คำนวณจากคำสั่ง) และ y (แรงบิดจริง) อยากหา a, b, c ที่ทำให้
```
y ≈ a·P + b·D + c
```
ใกล้เคียงที่สุด **"ใกล้เคียงที่สุด" = ผลรวมของ (y − ค่าที่ทำนาย)² น้อยที่สุด** นี่คือ least squares

| ตัวแปร | ความหมาย | ถ้ามอเตอร์ทำตามสั่งเป๊ะ |
|---|---|---|
| a = `kp x` | kp ที่ใช้จริง / kp ที่สั่ง | 1 |
| b = `kd x` | kd ที่ใช้จริง / kd ที่สั่ง | 1 |
| c = offset | `tau_est` เลื่อนไปคงที่ (Nm) | 0 |

## เขียนเป็นเมทริกซ์
```
⎡ P₁  D₁  1 ⎤          ⎡ y₁ ⎤
⎢ P₂  D₂  1 ⎥ ⎡a⎤      ⎢ y₂ ⎥
⎢ ⋮   ⋮   ⋮ ⎥ ⎢b⎥  ≈   ⎢ ⋮  ⎥        X · θ ≈ y
⎣ P_N D_N 1 ⎦ ⎣c⎦      ⎣ y_N⎦
    X (N×3)    θ        y (N)
```
- คอลัมน์ `1` คือสิ่งที่ทำให้มี offset ถ้าไม่ใส่ แปลว่าบังคับ c = 0
- numpy: `np.linalg.lstsq(X, y, rcond=None)[0]` คืน θ = (a, b, c)
- สร้าง X: `np.column_stack([P, D, np.ones_like(P)])`

## ทดสอบโค้ดกับข้อมูลปลอมก่อนเสมอ (6.4)
ก่อนเอาไปใช้กับข้อมูลจริง ให้สร้างข้อมูลที่**รู้คำตอบอยู่แล้ว**:
```
P = สุ่ม N ค่า, D = สุ่ม N ค่า
y = 0.93·P + 0.86·D − 0.28 + noise เล็กๆ
fit → ต้องได้ ≈ (0.93, 0.86, −0.28)
```
ถ้าไม่ได้ แปลว่าโค้ด fit ผิด ไม่ใช่ข้อมูลผิด **นี่คือนิสัยสำคัญที่สุดของงานวิเคราะห์ข้อมูล**
ลองต่อ: ใส่ noise มากขึ้น, ลด N, ทำให้ D เล็กมากจนเกือบเป็น 0 แล้ว b ยังเชื่อได้ไหม

## ทำไมต้องมี offset (6.5)
`tau_est` ประมาณจากกระแสของมอเตอร์ อาจมีค่าเลื่อนคงที่ 0.1–0.3 Nm (เช่นเข่าซ้าย −0.28, ศอกขวา +0.15)

**ตัวอย่างตัวเลข ศอกแขน (kp 14.3):**
- ช่วงค้างท่า แรงบิดจริงแค่ ~0.5 Nm
- offset 0.15 Nm = 30% ของสัญญาณ
- ถ้าไม่ใส่ c ใน fit, a ต้อง "ดูดซับ" offset ไว้เอง → `kp x` เพี้ยนไปมาก (vault: ศอกขวา 0.70 ดิบ → 0.96 มี offset)

**ส่วนเข่า (kp 99.1):** แรงบิดใหญ่หลาย Nm ทำให้ offset 0.28 Nm กระทบน้อยกว่า

## ทำไม fit ทั้งไฟล์ (ไม่มี offset) ได้ค่าเพี้ยน (6.5)
ทั้งไฟล์มีช่วง hold นานกว่าช่วง step มาก ช่วง hold แรงบิดเล็ก P เกือบคงที่ (≈ แรงโน้มถ่วง/kp) ทำให้:
- offset กับ friction มีผลเป็นสัดส่วนใหญ่
- ข้อมูลที่ "บอก" เรื่อง kp จริงๆ คือช่วงที่ P เปลี่ยนมาก ซึ่งก็คือช่วง step
→ `pd_check --segments` จึง fit เฉพาะ `[t0, t1]` ของ test นั้น และเฉพาะข้อต่อที่ถูกทดสอบ
(vault: ทั้งไฟล์ ศอกขวา 0.61, เข่าซ้าย 0.77 → เฉพาะช่วง step + offset 0.96, 0.93)

**เพี้ยนไปทางไหนขึ้นกับเครื่องหมายของ offset** ไม่ใช่ต่ำเสมอ: วัดจริง 10/11 ศอกขวา offset +0.14 → kp x 0.70 (ต่ำ) แต่ศอกซ้าย offset −0.12 → kp x **1.17** (สูง)

## Omitted variable bias (6.8 ก)
ถ้า P กับ D **สัมพันธ์กัน** (เช่นตอน step: q_des กระโดด → P ใหญ่ แล้ว q วิ่งตาม → dq ใหญ่ → D ใหญ่ในทิศตรงข้าม) แล้วเราตัด D ทิ้ง:
```
y = a·P + b·D        แต่ fit แค่  y ≈ a'·P
→ a' = a + b · (ส่วนของ D ที่ "ดูเหมือน" P)          ≠ a
```
a' จะรับแรงของ D ไปแทน `pd_check` จึงเก็บทั้งสอง term ไว้ใน fit เสมอ แม้ term ไหนเล็กจนไม่รายงานผล (comment ใน `fit_pd()`, vault: ไหล่ roll ใน sim 0.67 → 0.99 หลังแก้)

## วัดว่า fit ดีแค่ไหน
| ค่า | สูตร | ดีคือ |
|---|---|---|
| corr | `np.corrcoef(X @ θ, y)[0,1]` | ≥ 0.9 (`pd_check` เตือนเมื่อ < 0.8 ต่อ segment) |
| residual RMS | `sqrt(mean((y − X@θ)²))` | เล็กเมื่อเทียบกับ RMS ของ y |
| RMS ของ P, D | `sqrt(mean(P²))` | ≥ 0.3 Nm ถึงจะรายงาน gain (`MIN_TAU_RMS`) ถ้าเล็กกว่านั้นเป็นแค่ noise |

## step กับ chirp
- **step:** P ใหญ่ชัด แต่ D ใหญ่แค่ช่วงสั้นๆ ตอนกระโดด → `kp x` เชื่อได้ ส่วน `kd x` เชื่อได้น้อยกว่า
- **chirp** (ความถี่ไล่ 0.3 → 2.5 Hz): ข้อต่อเคลื่อนเร็วต่อเนื่อง → D ใหญ่ตลอด → ได้ `kd x` ที่ดี
- ข้อมูล 3/11 มีแค่ step จึงตีความ `kd x` อย่างระวัง (vault: `kd x` ที่ gain ตอนเทรนบนหุ่นจริงด้วย chirp **ยังไม่ได้วัด**)

## คำถามเช็ค
1. ถ้า P เป็นค่าคงที่ตลอดช่วง (ไม่เปลี่ยนเลย) จะแยก a ออกจาก c ได้ไหม เพราะอะไร
2. 6.8 (ง): ถ้าใน "สูตร" ใช้ kd = 2 × ของจริง คิดว่า b ที่ fit ได้จะเป็นเท่าไหร่ อธิบายด้วยพีชคณิต
3. ทำไมต้องทดสอบกับข้อมูลปลอมก่อน ทั้งที่มีข้อมูลจริงอยู่แล้ว
