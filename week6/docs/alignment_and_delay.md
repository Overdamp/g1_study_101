# จับคู่ lowcmd กับ lowstate และหา delay

## ปัญหา
- lowstate มา ~1 kHz ส่วน lowcmd มา ~550 Hz คนละจังหวะกัน
- ณ เวลาของ lowstate แต่ละแถว เราต้องรู้ว่า "มอเตอร์กำลังใช้คำสั่งไหนอยู่" จึงจะคำนวณได้ว่าแรงบิดควรเป็นเท่าไหร่

## Zero-order hold
มอเตอร์ใช้คำสั่งล่าสุดที่ได้รับ จนกว่าจะมีคำสั่งใหม่ (sim ก็ทำแบบนี้ สัปดาห์ 2)
```
cmd:    c0 ─────── c1 ────── c2 ─────── c3
state:    s0  s1  s2   s3  s4   s5  s6
ใช้:      c0  c0  c1   c1  c1   c2  c2
```
วิธีหา index ของคำสั่งที่มีผล:
```
j = searchsorted(cmd_t, state_t − delay, side="right") − 1
```
- `searchsorted(..., side="right")` คืนตำแหน่งที่จะแทรก `state_t` ลงใน `cmd_t` แล้ว −1 ก็จะได้คำสั่ง**ล่าสุดที่มาก่อนหรือพร้อมกับ** เวลานั้น
- `j < 0` แปลว่าแถวนั้นมาก่อนคำสั่งแรก ให้ทิ้ง
- นี่คือ `expected_torque()` ใน `pd_check.py` (ลองเขียนเองก่อนเปิดดู)

**ทดสอบมือ:** `cmd_t = [0, 10, 20]`, `state_t = [5, 10, 15, 25]`, delay 0 → j ควรเป็นเท่าไหร่ (ทายก่อน แล้วลองใน `python`)

## Delay
คำสั่งไม่ได้มีผลทันทีที่ publish ต้องผ่าน DDS → สาย LAN → board → driver มอเตอร์ ถ้าใช้คำสั่งผิดตัว (เร็วไป 1–3 ms) ระหว่างช่วงที่ q_des กระโดด แรงบิดที่คาดจะผิดมาก และทำให้ gain ที่ fit ได้เพี้ยน
```
ทำไมต้องหา delay ก่อน fit gain:
  delay จริง 3 ms แต่ใช้ 0  → ช่วง step แรงบิดที่คาดนำหน้าของจริง 3 ms
                           → least squares พยายามอธิบายส่วนที่ไม่ตรงด้วยการปรับ a, b → gain เพี้ยน
```

### หา delay ด้วยการกวาด (6.6)
```
for delay in 0, 1, 2, ..., 30 ms:
    คำนวณ P, D ด้วย delay นี้
    fit → ได้ residual (หรือ corr)
เลือก delay ที่ residual ต่ำสุด
```
- ค่าอ้างอิง: `pd_check` ได้ **3 ms** กับเข่าซ้าย 3/11 (vault: 30/10 ก็ 3 ms, 3/11 อยู่ในช่วง 0–4 ms)
- `pd_check.py` จำกัดการค้นหาไว้ที่ `MAX_CMD_DELAY_S = 0.03`
- **ทายก่อน:** กราฟ residual กับ delay จะมีหน้าตายังไง มีจุดต่ำสุดจุดเดียวชัดๆ หรือแบน

### ข้อควรระวัง
- ความละเอียดของ delay จำกัดด้วยอัตราของ cmd (~1.8 ms ต่อคำสั่ง) ค่า 2 ms กับ 3 ms อาจแยกกันได้ไม่ชัด
- delay ที่ได้รวม "เวลาที่ monitor รับ cmd" กับ "เวลาที่ monitor รับ state" ด้วย ไม่ใช่ latency ของมอเตอร์ล้วนๆ
- ช่วงที่ q_des คงที่ (hold) ไม่ให้ข้อมูลเรื่อง delay เลย ข้อมูลส่วนใหญ่มาจากขอบของ step

## สร้าง P, D, y สำหรับ fit
ต่อข้อต่อ `i` (เช่น slot 3) ณ แถว state ที่จับคู่ได้:
```
P  = kp[j,i] · (q_des[j,i]  − q[i])        # ส่วนสปริงที่ "ควร" เป็น  (Nm)
D  = kd[j,i] · (dq_des[j,i] − dq[i])       # ส่วนโช้คที่ "ควร" เป็น  (Nm)
ff = tau_ff[j,i]
y  = tau_est[i] − ff                       # แรงบิดจริงที่ต้องอธิบาย
```
ถ้ามอเตอร์ทำตามที่สั่งทุกประการ: `y = 1·P + 1·D` → fit แล้วได้ a = b = 1

## คำถามเช็ค
1. ถ้าใช้ "คำสั่งที่ใกล้ที่สุด" (ทั้งก่อนและหลัง) แทน zero-order hold จะผิดตรงไหน
2. ทำไมช่วง hold ไม่ช่วยหา delay
3. delay ที่วัดได้ 3 ms ต่างจาก DR action delay 0–20 ms ตอนเทรน (สัปดาห์ 5) อยู่ในช่วงที่ policy ทนได้ไหม
