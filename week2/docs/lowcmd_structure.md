# โครงสร้าง `rt/lowcmd` (unitree_hg::LowCmd_)

ที่มา: `unitree_sdk2py/idl/unitree_hg/msg/dds_/_LowCmd_.py`, `_MotorCmd_.py`
(G1 ใช้ชุด **hg** ถ้าใช้ชุด go ฝั่งรับจะไม่ได้ยินเลยเหมือนสัปดาห์ 1)

## ภาพรวม
```
LowCmd_
├── mode_pr        uint8     โหมดข้อเท้า (PR / AB)
├── mode_machine   uint8     รุ่นหุ่น ต้องตรงกับ LowState.mode_machine (23-DoF = 4)
├── motor_cmd[35]  MotorCmd_ คำสั่งต่อมอเตอร์ (slot เดียวกับ motor_state)
│   ├── mode       uint8     1 = เปิดมอเตอร์, 0 = ปิด
│   ├── q          float32   มุมเป้าหมาย        [rad]
│   ├── dq         float32   ความเร็วเป้าหมาย    [rad/s]  ปกติ 0
│   ├── tau        float32   แรงบิดป้อนตรง (feed-forward) [Nm]  ปกติ 0
│   ├── kp         float32   stiffness          [Nm/rad]
│   ├── kd         float32   damping            [Nm·s/rad]
│   └── reserve
├── reserve[4]
└── crc            uint32    checksum ของทั้งข้อความ คำนวณเป็นขั้นสุดท้ายก่อนส่ง
```

**เทียบกับ LowState:** `motor_state[i]` คือ "ตอนนี้เป็นยังไง" ส่วน `motor_cmd[i]` คือ "อยากให้เป็นยังไง" **slot เดียวกัน** ศอกซ้ายเป็น 18 ทั้งคู่

## แต่ละ field ไว้ทำอะไร

### `motor_cmd[i]`: 5 ค่าที่ใช้สร้างแรงบิด
มอเตอร์ไม่ได้รับ "แรงบิด" ตรงๆ แต่รับ **เป้าหมาย + ความแข็ง** แล้วคำนวณเอง:
```
tau_out = tau + kp·(q − q_now) + kd·(dq − dq_now)
```
(รายละเอียดอยู่ใน `pd_control.md`)

| อยากได้ | ตั้งค่า |
|---|---|
| ปล่อยอิสระ | kp = 0, kd = 0, tau = 0 |
| หนืด (damping) | kp = 0, kd > 0 |
| ค้างท่า | kp > 0, kd > 0, q = มุมที่อยากค้าง |

### `mode` (ต่อมอเตอร์)
บนหุ่นจริง `1` = เปิดมอเตอร์ ถ้าเป็น `0` มอเตอร์จะไม่ทำตามคำสั่ง ตัวอย่างของ Unitree ตั้ง `mode = 1` ให้ทุกช่อง
→ ใน sim ใช้ field นี้ไหม? ลองดูในงาน 2.8 (ข)

### `mode_machine`
บอกว่าคำสั่งนี้ทำมาสำหรับหุ่นรุ่นไหน ตัวอย่างของ Unitree **อ่านค่านี้จาก LowState ก่อน** แล้วค่อยใส่กลับลงใน LowCmd (ดู `update_mode_machine_` ใน `g1_low_level_example.py`) ไม่ได้ hard-code เอง

### `mode_pr`
ข้อเท้าของ G1 ขับด้วยมอเตอร์ 2 ตัวผ่านก้านต่อ
- **PR** = สั่งเป็น pitch / roll (แบบที่เราคิดเป็นมุมข้อต่อ)
- **AB** = สั่งมอเตอร์ A / B ตรงๆ
งานสัปดาห์นี้สั่งแค่ศอก ใช้ PR (= 0) ตามตัวอย่างไปก่อน

### `crc`
checksum (CRC32) ของทั้งข้อความ ฝั่งรับคำนวณซ้ำแล้วเทียบ ถ้าไม่ตรงถือว่าข้อความเสีย
- **ต้องคำนวณเป็นขั้นสุดท้าย** หลังจากใส่ค่าทุก field แล้ว ถ้าแก้ field ไหนหลังคำนวณ CRC ก็จะผิดทันที
- ใช้ `CRC().Crc(low_cmd)` จาก `unitree_sdk2py/utils/crc.py`

## สร้าง LowCmd เปล่า
ใน `unitree_sdk2py/idl/default.py` มีฟังก์ชันที่สร้าง message ซึ่งทุก field เป็น 0 ไว้ให้แล้ว (ดูบรรทัด import ในตัวอย่าง G1) ใช้ตัวนี้แทนการสร้าง `LowCmd_(...)` เองทีละ field

## ⚠️ ข้อสังเกตเรื่อง slot ที่ไม่มีข้อต่อ
slot 13, 14, 20, 21, 27, 28 ไม่มีข้อต่อบน 23-DoF ส่วนโมเดลใน sim (`g1_23dof.xml`) ยังมีมอเตอร์ครบ 29 ตัวตามลำดับ slot ปล่อยช่องเหล่านี้เป็น 0 ไว้ก็พอ

## เติมเอง (งาน 2.1)
ตอบด้วยคำของตัวเอง ไม่ต้องก็อปจากข้างบน

| คำถาม | คำตอบของฉัน |
|---|---|
| ถ้าอยากให้ศอกค้างที่ 60° ต้องตั้ง field ไหนเป็นค่าเท่าไหร่ (หน่วย!) | |
| ถ้าลืมตั้ง `kp` (ปล่อยเป็น 0) แต่ตั้ง `q` แล้ว จะเกิดอะไร | |
| ทำไมต้องอ่าน `mode_machine` จาก LowState แทนการพิมพ์ 4 ลงไปเลย | |
| ทำไม CRC ต้องคำนวณเป็นขั้นสุดท้าย | |
| field ไหนบ้างที่ไม่มีใน LowState แต่มีใน LowCmd และกลับกัน | |
