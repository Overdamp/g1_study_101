# PD control: kp, kd ทางฟิสิกส์

อ่านคู่กับ vault `01 Concepts/PD Control.md` (ไฟล์นี้เน้นส่วนที่ใช้ทำงานสัปดาห์ 2)

## สูตร
```
tau = kp·(q_des − q) + kd·(dq_des − dq) + tau_ff
       └─ สปริง ─┘     └──── โช้ค ────┘   └ ป้อนตรง ┘
```

| ส่วน | ฟิสิกส์ | หน่วย | ความหมาย |
|---|---|---|---|
| `kp·(q_des − q)` | สปริงบิด | kp: Nm/rad | ห่างเป้า 1 rad จะถูกดึงกลับด้วยแรง kp Nm |
| `kd·(dq_des − dq)` | โช้ค / ความหนืด | kd: Nm·s/rad | หมุนเร็ว 1 rad/s จะถูกต้านด้วยแรง kd Nm |
| `tau_ff` | แรงที่ใส่ตรงๆ | Nm | เช่น ชดเชยแรงโน้มถ่วง (สัปดาห์นี้ = 0) |

**นึกภาพ:** ศอกติดสปริง (kp) ที่ดึงไปหามุม `q_des` และติดโช้ค (kd) ที่ไม่ยอมให้ขยับเร็ว

## ตัวอย่างตัวเลขจากหุ่นเรา (gain แขนตอนเทรน: kp 14.3, kd 0.9)
| สถานการณ์ | คำนวณ | tau |
|---|---|---|
| ศอกห่างเป้า 0.1 rad (≈5.7°) อยู่นิ่ง | 14.3 × 0.1 | **1.43 Nm** |
| ศอกห่างเป้า 0.5 rad (≈28.6°) อยู่นิ่ง | 14.3 × 0.5 | **7.15 Nm** |
| ศอกอยู่ที่เป้าพอดี แต่หมุนอยู่ 2 rad/s | 0.9 × (0 − 2) | **−1.8 Nm** (ต้านการหมุน) |
| step +30° (0.524 rad) ทันที ตอนเริ่ม | 14.3 × 0.524 | **7.5 Nm** |

ลิมิตแรงบิดศอกใน sim: ±25 Nm (`ctrlrange` ใน `g1_23dof.xml`) ถ้าใส่ kp สูงแล้ว step ใหญ่ แรงอาจชนลิมิต

## ทำไมห้อยค้างแล้วไม่ถึงเป้าพอดี
ตอนนิ่ง (dq = 0) แรงสปริงต้องเท่ากับแรงโน้มถ่วงที่ดึงแขน:
```
kp·(q_des − q) = tau_gravity    →    error = tau_gravity / kp
```
- kp ยิ่งสูง error ยิ่งเล็ก แต่ไม่มีวันเป็น 0 ถ้ามีแรงโน้มถ่วงและไม่มี `tau_ff`
- นี่คือเหตุผลที่โจทย์ 2.4 ให้ "คลาดเคลื่อน < 2°" ไม่ใช่ 0°
- งานท้าทาย: ใส่ `tau_ff` ชดเชยแรงโน้มถ่วง แล้ว error จะเหลือเท่าไหร่

## kp / kd ส่งผลต่อ step response ยังไง
```
มุม
 ▲        kp สูง kd ต่ำ: ขึ้นเร็ว พุ่งเกิน แกว่ง
 │       ╭╮
 │──────╯──╰─╮╭──────────  q_des
 │     ╱      ╰╯
 │    ╱   ╭────────────     kp/kd พอดี: ขึ้นเร็ว ไม่เกิน
 │   ╱  ╱
 │  ╱ ╱     ............    kp ต่ำ: ขึ้นช้า และค้างต่ำกว่าเป้า (แรงโน้มถ่วง)
 │ ╱╱  .....
 └────────────────────────▶ เวลา
```

| ปรับ | ผล |
|---|---|
| kp ↑ | ขึ้นเร็วขึ้น error ตอนนิ่งน้อยลง แต่ถ้า kd ไม่พอจะพุ่งเกินและแกว่ง |
| kd ↑ | แกว่งน้อยลง แต่ถ้ามากไปจะช้าและหนืด |
| kd = 0 | ไม่มีอะไรดูดพลังงาน แกว่งนาน (ใน sim เหลือแค่ damping/friction ของโมเดล) |

**คำจำกัดความที่ใช้วัด (งาน 2.5–2.6)**
- **rise time:** เวลาที่ใช้จาก 10% ไปถึง 90% ของระยะ step
- **overshoot:** เกินเป้าไปสูงสุดกี่ % ของระยะ step
- **steady-state error:** ห่างเป้าเท่าไหร่ตอนนิ่งแล้ว

## gain ของหุ่นเรา (BeyondMimic ตอนเทรน)
| กลุ่มข้อต่อ | kp | kd |
|---|---|---|
| แขน (ไหล่ ศอก ข้อมือ) | 14.3 | 0.9 |
| hip pitch / yaw, เอว | 40.2 | 2.6 |
| hip roll, เข่า | 99.1 | 6.3 |
| ข้อเท้า | 28.5 | 1.8 |

สังเกตว่า kd/kp ของทุกกลุ่ม ≈ 0.063 เท่ากันหมด (ลองคิดว่าทำไม ใบ้: ดู vault `Armature and Gains.md`)

## ทำไม gain สำคัญกับ RL
policy ไม่ได้สั่งแรงบิด แต่สั่ง `q_des` แล้วให้ PD แปลงเป็นแรง ระหว่างเทรน policy เรียนรู้ว่า "สั่งเป้าเท่านี้ ข้อต่อจะไปถึงแค่ไหน" ภายใต้ kp/kd ชุดหนึ่ง **ถ้าเปลี่ยน gain ตอน deploy ก็เหมือนเปลี่ยนหุ่นที่ policy ไม่เคยเจอมาก่อน**
งาน 2.6 จะทำให้เห็นกับตาว่า q_des เดียวกัน แต่ kp ต่างกัน ข้อต่อไปได้ไม่เท่ากัน

## คำถามเช็ค
1. kp = 14.3 ศอกห่างเป้า 10° ได้แรงบิดเท่าไหร่ (ระวังหน่วย)
2. ถ้าอยากให้ error ตอนห้อยค้างลดลงครึ่งหนึ่ง โดยไม่ใช้ `tau_ff` ต้องเปลี่ยน kp เป็นเท่าไหร่ แล้วต้องระวังอะไร
3. ตอน damping (kp = 0) ลากแขนช้าๆ กับลากเร็วๆ รู้สึกต่างกันยังไง เพราะอะไร
