# sim กับหุ่นจริง: รับ `rt/lowcmd` ต่างกันยังไง

## sim ทำอะไรกับคำสั่ง (อ่านจาก source จริง)
`~/nvidia/unitree/unitree_mujoco/simulate/src/unitree_sdk2_bridge.h` ฟังก์ชัน `run()` ถูกเรียกทุก 1 ms:

```cpp
for (int i = 0; i < num_motor_; i++) {
    auto & m = lowcmd->msg_.motor_cmd()[i];
    mj_data_->ctrl[i] = m.tau()
                      + m.kp() * (m.q()  - sensordata[i])               // q ปัจจุบัน
                      + m.kd() * (m.dq() - sensordata[i + num_motor_]); // dq ปัจจุบัน
}
```

สิ่งที่อ่านได้จากโค้ดนี้:
1. **sim ใช้สูตร PD เดียวกับใน `pd_control.md`** คำนวณใหม่ทุก 1 ms จาก state ล่าสุด
2. **sim ใช้แค่ 5 field:** `tau, kp, q, kd, dq` ในโค้ดนี้ไม่ได้อ่าน `mode`, `mode_machine`, `crc`
   → งาน 2.8 ให้ทดลองเองว่าจริงไหม (ทายก่อน)
3. **sim เก็บคำสั่งล่าสุดไว้ใช้ต่อ** (`lowcmd->msg_`) ถ้าโปรแกรมเราหยุดส่ง sim ก็ใช้คำสั่งสุดท้ายต่อไปเรื่อยๆ
   → งาน 2.8 (ค): หยุดโปรแกรมตอนศอกค้างอยู่ แขนจะทำอะไร
4. ก่อนมีคนส่งคำสั่งมาเลย ทุกค่าเป็น 0 ทำให้ข้อต่อปล่อยอิสระ (นี่คือเหตุผลที่ศอกห้อยอยู่ที่ 69° ในงาน 1.4)

## ตารางเทียบ
| เรื่อง | sim (unitree_mujoco) | หุ่นจริง |
|---|---|---|
| สูตร PD | คำนวณใน `run()` ทุก 1 ms | คำนวณใน driver ของมอเตอร์ ถี่กว่ามาก |
| `mode` = 0 | (ทดลองเอง 2.8 ข) | มอเตอร์ไม่ทำตาม |
| CRC ผิด | (ทดลองเอง 2.8 ก) | ทิ้งข้อความนั้น |
| `mode_machine` ผิด | (ทดลองเอง) | ไม่ทำตามคำสั่ง |
| หยุดส่งคำสั่ง | ใช้คำสั่งสุดท้ายต่อไป | มี watchdog ของ firmware (vault `PD Control.md`) |
| ข้อเท้า | joint ตรงๆ ในโมเดล | มอเตอร์ 2 ตัว + ก้านต่อ แปลง PR↔AB ใน firmware |
| แรงบิดสูงสุด | `ctrlrange` ใน xml (ศอก ±25 Nm) | จำกัดกระแส + ป้องกันความร้อน |
| ความร้อน | ไม่จำลอง (`temperature` = 0) | มี ร้อนแล้วลดแรง |
| friction / armature | ค่าคงที่ในโมเดล (`frictionloss 0.2`, `armature 0.01` ฯลฯ) | ของจริง เปลี่ยนตามอุณหภูมิและการสึก |

**บทเรียน:** โค้ดที่ "ใช้ได้ใน sim" อาจไม่ผ่านบนหุ่นจริง ถ้าลืม `mode`, `mode_machine`, หรือ CRC เพราะ sim ไม่ฟ้อง จึงควรเขียนให้ถูกตามหุ่นจริงตั้งแต่แรก แม้ sim จะไม่บังคับ

## ทำไมห้ามมี 2 โปรแกรมส่ง `rt/lowcmd` พร้อมกัน
DDS ส่งทุกข้อความถึงผู้รับทุกตัว ฝั่งรับไม่รู้ว่าข้อความไหนมาจากใคร sim/หุ่นจะใช้ "ข้อความที่มาถึงล่าสุด" เมื่อ 2 โปรแกรมส่งสลับกัน:
```
t=0ms  A: ศอก q=0.5 kp=14   → ใช้ของ A
t=1ms  B: ศอก q=1.2 kp=40   → ใช้ของ B
t=2ms  A: ศอก q=0.5 kp=14   → ใช้ของ A  ...
```
ข้อต่อจะถูกดึงไปมาระหว่าง 2 เป้าหมายทุก ms ทำให้สั่นรุนแรง บนหุ่นจริงอันตรายมาก
→ ก่อนส่ง ควรเช็คก่อนว่ามีคนอื่นส่ง `rt/lowcmd` อยู่ไหม (subscribe ฟังดูก่อน 1 วินาที) เครื่องมือของ repo ก็ทำแบบนี้ (`motion_mode.py check`)

## ทำไมต้องส่งต่อเนื่อง ไม่ส่งครั้งเดียว
- **หุ่นจริง:** firmware มี watchdog ถ้าคำสั่งหายไปนาน จะถือว่าโปรแกรมควบคุมตาย
- **ทั้งคู่:** เป้าหมายที่ดีมักเปลี่ยนตามเวลา (ค่อยๆ เลื่อนไปหาเป้า, policy ส่งใหม่ทุก step)
- **DDS:** ข้อความอาจหายระหว่างทาง การส่งซ้ำต่อเนื่องจึงทนทานกว่า

## คำถามเช็ค
1. ถ้าเขียนโค้ดที่ลืม `mode = 1` แล้วทดสอบใน sim ผ่าน จะเกิดอะไรเมื่อเอาไปรันบนหุ่นจริง
2. งาน 1.4 ศอกห้อยที่ 69° เป็นเพราะ sim ได้รับคำสั่งแบบไหน
3. ถ้า policy (โปรแกรม A) รันอยู่ แล้วคุณเปิด `send_zero.py` (โปรแกรม B) ขึ้นมา หุ่นจะเป็นยังไง
